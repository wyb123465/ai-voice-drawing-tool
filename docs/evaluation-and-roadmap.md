## 0. 赛题原文（评分基准的唯一来源）

> **题目二：AI 语音绘图工具**
> 请开发一款纯语音控制的绘图工具。
> 要求：用户不能使用鼠标或键盘，仅通过语音指令完成绘图创作。请综合考虑
> **指令理解的准确性与容错性**、**语音到绘图操作的响应延迟**，以及**复杂指令的拆解与执行能力**。
> 实现应用的同时，请额外提交一份**设计文档**，记录你计划支持哪些指令能力、最终实现了哪些、以及未完成部分的原因说明。

赛题**明确点名**的评分轴只有四条 + 一份文档：

1. 指令理解的**准确性**
2. 指令理解的**容错性**
3. 语音到绘图的**响应延迟**
4. 复杂指令的**拆解与执行能力**
5. **设计文档**（计划 / 实现 / 未完成原因）

赛题**没有要求**：LLM / 大模型、Agent 架构、连续对话、多轮指代消解、创新性。
这些不是欠债，做了属于**超额交付**，可作为加分亮点（见第 6 节），但不应作为扣分项。

## 1. 一句话结论

当前作品的本质是：**一个工程素养很好的「中文规则解析 + Canvas 简笔画 + 串行执行」工具**，
真正干活的是 `commands.js` 里约 580 行的中文解析；外层可选的 LLM 兜底是**超出赛题要求**的扩展能力。

- **按赛题真实评分轴：约 43 / 50（诚实区间 42–44）。**
- **定位：前 15%，一等奖有竞争力；剩余差距主要在更开放的自然语言表达与更完整多轮选择。**
- 本轮已补齐三个**赛题内**的高收益缺口：**容错（ASR 错字纠错）**、**准确性（焦点指代消解）** 与 **错误恢复（一轮澄清追问）**。

> 说明：本文档第一版草评曾按"AI Agent 冠军级"框架给到 29/50，
> 后经对照赛题原文校准——撤回所有"赛题未要求"的扣分（Agent 化、现场真 LLM、多轮对话、创新性权重），
> 保留所有"赛题内"的缺口（容错、指代）。本轮 P0 优化后，最终分数以本文档当前版本为准。

## 3. 指代消解：本轮已修复的"准确性"缺口

以一句复合指令 **"画一个圆，在它右边画一个正方形，然后把它改成红色"** 按代码逐句走查：

1. **"画一个圆"** → `draw circle`，状态层把圆设为 `focusId` ✅
2. **"在它右边画一个正方形"** → `parseRelation`=`right-of`；锚点"它"解析为 `anchorShape: "focus"`，绘制时锚定圆，并通过 `preserveFocus` 保留圆为焦点 ✅
3. **"把它改成红色"**：
   - `resolveTarget("把它改成红色")`：命中指代词 → 返回 `focus`
   - `findTargetIndex` 优先查找 `state.focusId`
   - `transformElement` 改**焦点对象 = 圆 → 涂红** ✅

**结果：系统把圆涂红，正方形保持原色。** 同时正方形现在是真正的等宽等高 `square`，画布上会显示当前焦点描边。

> 严重度说明：该 P0 缺口已经补齐。剩余问题不是"不会指代"，而是遇到真实歧义时还不会反问。

逐项体检：

| 能力 | 现状 | 判定 |
| --- | --- | --- |
| 模糊表达（词表外） | 一部分低置信移动表达会反问，开放世界表达仍有限 | ⚠️ |
| 歧义消解（"它"指圆还是方） | 有焦点规则；低置信动作有一轮反问 | ✅/⚠️ |
| 指代消解（它/这个/那个） | → `focus`，不再一律 `last` | ✅ |
| 上下文记忆 | `focusId` + `lastShape`，可跨连续命令应用 | ✅ |
| 连续命令执行 | `utteranceQueue` 串行可跑，状态焦点随执行更新 | ✅ |

## 4. 用户旅程（评委即兴使用，而非录好的 demo 脚本）

1. 打开页面 → 👍 干净，看板 + AI 兜底面板，第一印象专业
2. 点"启动语音"授权 → 👍 顺
3. "画一个红色的圆" → 👍 秒出（爽点）
4. "画一只猫"（默认规则模式）→ ⚠️ 规则未执行；但右侧有"试试：画一只猫"可见 AI 兜底演示入口
5. "把它往右挪一点" → 👍 能动（`parseMove`）
6. "画个圆，在它右边画方块，把它涂红" → 👍 圆被涂红，方块保持原色，焦点描边可见
7. 换说法"整个三角形上去" → 👍 系统先问"是否把三角形向上移动"，听到"对"后执行
8. ASR 把"画个圆"听成"画个园/元" → 👍 常见错字已归入圆形解析；"兰色/桔色"也可兜住

**结论：录好的 demo 脚本里 UX≈9 分，评委即兴乱说时从 ≈4 分提升到 ≈7 分。**
现在最容易露馅的不是指代、ASR 常见错字或基础澄清，而是更开放的词表外创作表达。

## 6. 可作为创新/亮点的方向（赛题不强制，但能加分）

> 这些是上一轮分析中提到、**即使本次赛题不要求、也能成为差异化亮点**的能力。
> 它们让作品从"完成赛题"升级为"完成赛题 + 有记忆、会反问、能理解没教过的话"。
> 建议在设计文档与 demo 中以"扩展能力 / 创新点"的口径呈现，而非"必做项"。

### 6.1 已落地、可直接当亮点讲（被赛题低估的超额交付）
- **规则优先 + LLM 兜底 + 白名单校验**：默认离线零成本，低置信度才调云端；
  云端开放输出必须过形状/颜色/位置白名单，密钥只走 Authorization 头、不进 URL/日志。
  这是成熟的工程范式，且**赛题并不要求**，属于纯加分。
- **无密钥演示链路（`?llmdemo=1`）**：用本地模拟 resolver 展示"低置信度 → 兜底 → 校验 → 绘制"全链路，
  让评委在无密钥环境也能看懂 AI 兜底设计。
- **可复现的评审入口**：`replay` / `demo` / `llmdemo` 参数 + 一键评审脚本 + 实时运行看板。
- **焦点对象 + 指代消解**：`focusId` 跟随绘制/编辑/复制/删除更新，"它/这个/那个"可指向当前焦点对象，并在画布上高亮。
- **ASR 常见错字容错**："画个园/元"可解析为圆，"兰色/桔色/橘色"可解析到蓝色/橙色。
- **一轮澄清追问**："整个三角形上去"这类低置信移动表达会先反问，听到"对"后再执行。
- **工程完成度**：58 个自动化测试、零运行时依赖、不可变状态 + 撤销重做、模块分离、CI/Pages 部署。

### 6.2 建议补的创新点（性价比最高，且正好补赛题缺口）
- **更完整的多候选澄清**：当前已支持一轮确认式澄清；下一步可扩展为
  "你是指刚才的圆还是正方形？"，听到"圆/前一个"再执行。
  → 这是更完整的多轮交互雏形，但不建议在提交前大改。
- **更开放的 ASR 容错**：在现有常见错字表基础上，增加低置信度反问，而不是盲目做大范围替换。
  → 避免把"写上元旦"误改成"圆旦"这类副作用。

### 6.3 可写进文档"未来工作"的更大创新（不建议 3 天内做）
- **Planner Agent**：把"画一个有太阳和山的风景，树在山前面"这类**未列举**的开放复合意图，
  规划成有序绘图计划（当前 `splitCompoundCommand` 是字符串切割，非语义规划）。
- **对象命名与多轮精确选择**："把这个叫小太阳"，后续用名字引用。
- **真·在线 LLM（默认可用）**：用最小代理（如 Cloudflare Worker）藏 key，
  让任意自然表达默认就能成图——把"可选扩展"变成"默认能力"。

## 9. 最终结论（最严格视角）

**当前方案最大的问题（赛题内）：**
1. 词表外开放表达仍有限——只对部分低置信移动表达做一轮确认，还不是完整自然语言 planner。
2. 多候选澄清仍有限——还不能在多个候选对象之间语音选择。
3. 真在线 LLM 仍是可选增强——不配置密钥时，开放表达主要靠本地规则与模拟兜底演示。

**最吸引评委的 3 个亮点：**
1. 工程完成度：58 测试全过、零依赖、不可变状态 + 撤销重做、模块分离、CI/Pages。
2. 赛题命中度：ASR 高频错字容错、焦点指代、选中高亮、一轮澄清都直接服务准确性与容错性。
3. 安全意识：LLM 白名单防越权、密钥只走 Header 不进 URL/日志。

**哪些属于无效开发（别再投入）：**
继续堆形状/颜色别名、给 mockResolver 加假规则、增加 demo/replay 变体、README 加 badge/emoji、
继续单纯堆测试数量——赛题语境下一分都加不了。

**如何最小成本提升获奖概率：**
P0 两项和一轮澄清已经完成。下一步若继续提升名次，不建议继续扩形状词典；
应优先录 demo 视频、回填视频链接，并把"澄清追问"作为讲解亮点。
