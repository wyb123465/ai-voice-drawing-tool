# XEngineer 提交说明

## 项目信息

- 参赛题目：第四批次议题二，AI 语音绘图工具。
- 项目名称：AI 语音绘图工具 / 声绘工作台。
- 核心目标：用户不使用鼠标或键盘，只通过语音完成绘图创作、对象编辑、撤销重做、清空和导出。
- 部署地址：https://wyb123465.github.io/ai-voice-drawing-tool/ （推送到 `main` 且 GitHub Pages Actions 成功后可访问）
- Demo 视频：[B 站：AI 语音绘图工具演示](https://www.bilibili.com/video/BV1b6JA63EbK/)，并同步填写到 README 与提交平台。
- 设计文档：[docs/design.md](./design.md)

## 用户价值与创新点

- 目标用户：不方便精细操作鼠标键盘、需要快速表达画面构思，或在演示/课堂中希望用自然语言生成草图的人。
- 核心痛点：传统绘图工具依赖工具栏、图层和快捷键，用户需要先学习操作方式；语音场景下还容易遇到识别错误、复杂句拆解失败和误操作已有对象的问题。
- 解决方案：把中文语音转为结构化绘图命令，由本地规则优先解析，低置信度才进入可选 LLM 兜底；所有云端输出再经白名单校验，最终落到 Canvas 可执行的安全命令。
- 创新点：支持一句话复合场景拆解、相对布局、序号对象选择、未知对象阻断、无密钥 LLM 链路演示，以及无麦克风文本回放，方便评审复现。

## Demo 视频建议脚本（总长 3–5 分钟）

**目标：正打赛题四轴（准确性 / 容错性 / 延迟 / 复杂拆解）+ 展示修复后的核心能力。**

### 第一幕：复杂指令拆解（赛题头牌，30秒）
1. 打开部署地址，点击“启动语音”，授权麦克风
2. 说：“**画一个太阳，下面有两座山，山前面有一棵树**”
3. 等画面出现，旁白：“系统自动拆解复合指令，按相对位置布局”
4. 说：“在左上角写上 XEngineer”

**评分点：复杂指令拆解与执行能力**

### 第二幕：焦点指代与准确性（核心修复，45秒）
5. 说：“画一个圆”
6. 说：“**在它右边画一个正方形**”（注意正方形是真正方形，focus 描边停在圆）
7. 说：“**把它改成红色**”（圆变红，不是方块）
8. 旁白：“系统跟踪焦点对象，'它'指向被引用的圆而非最后绘制的正方形；画布上虚线高亮显示当前焦点”

**评分点：指令理解准确性 + 焦点对象可视化**

### 第三幕：ASR 容错（赛题点名轴，30秒）
9. 说：“**画一个园**”（故意用同音字“园”）
10. 画面出现圆，旁白：“常见 ASR 错字自动纠正：园/元→圆”
11. 说：“**把它改成兰色**”（错字“兰”）
12. 圆变蓝，旁白：“兰色→蓝色，桔色→橙色等高频错字已内置映射”

**评分点：指令理解容错性**

### 第四幕：澄清追问（容错+多轮，45秒）
13. 说：“画一个三角形”
14. 说：“**三角形上去**”（模糊表达，缺“移动”动词）
15. 系统语音反问：“**请确认：你是想把三角形向上移动吗？请说'对'确认，或说'取消'**”
16. 说：“对”
17. 三角形上移，旁白：“低置信度表达会先澄清再执行，避免误操作”
18. 说：“**把这个圆上去**”（指代词+形状名）
19. 系统反问确认后执行，旁白：“指代词和形状名可交叉验证，不会误操作其他对象”

**评分点：容错性 + 多轮交互雏形**

### 第五幕：序号选择与编辑（30秒）
20. 说：“画一个红色圆，再画一个蓝色圆，再画一个绿色圆”
21. 说：“**删除第二个圆**”（蓝色圆消失）
22. 说：“**把第一个圆变大**”
23. 旁白：“支持序号选择与颜色筛选，不会误改其他对象”

**评分点：准确性 + 容错性（未知对象阻断的反面：已知对象精确选择）**

### 第六幕：撤销重做与导出（15秒）
24. 说：“撤销上一步”
25. 说：“重做”
26. 说：“导出图片”（下载触发）
27. 旁白：“完整的撤销重做栈 + 导出能力”

**评分点：功能完成度**

### 第七幕：LLM 兜底演示（可选，30秒）
28. 刷新页面，打开 `?llmdemo=1` 链接
29. 说：“**画一只猫**”（规则外）
30. 画面出现圆形（最接近映射），右侧日志标注“**云端·模拟**”
31. 旁白：“开放表达进入 LLM 兜底，经白名单校验后绘制；本地模拟演示不发网络请求，真实场景可配置 OpenAI 兼容 API”

**评分点：创新点（超出赛题要求的扩展能力）**

### 收尾（10秒）
32. 展示右侧运行看板（对象数、历史步数、解析来源、最近动作）
33. 旁白：“项目包含 75 个自动化测试，支持无麦克风文本回放，方便评审复现”
34. 最后 5 秒显示 GitHub 链接

---

### 录制要求

- **不要录失败 case**：评委看 demo 是确认“能用”，不是 debug
- **旁白节奏慢一点**：语音识别 + 绘制 + 反馈有延迟，别抢着说下一句
- **右侧日志面板保持可见**：展示“规则 / 澄清确认 / 云端·模拟”等来源标签
- **焦点描边可见**：确认录屏时画布上的虚线高亮框清晰（这是准确性的可视化证明）
- **视频开头**：展示仓库 README 或部署地址，确认是公开可访问的
- **视频结尾**：留 GitHub 链接 5 秒，评委要找代码
- **上传后**：匿名窗口测试链接可打开，再填写到 README 和提交平台

## 评分点对应

- 指令理解准确性：支持颜色、形状、位置、相对布局、复合场景、序号选择、颜色筛选、焦点指代、指代+形状交叉验证和未知对象阻断。
- 容错性：未识别或未知对象不会误改画布；“写上再见”不会被错误拆分；“删除第二个圆”作用于第 N 个匹配对象；“园/元/兰色/桔色”等常见 ASR 偏差可被纠正；“整个三角形上去”“把它上去”“把这个圆上去”这类低置信表达会先澄清确认再执行，“把那个圆挪上去”可直接解析为焦点圆移动；点名不存在的形状不会进入澄清、误画或执行缩放/换色。
- 响应延迟：默认本地规则解析，不配置密钥时不调用云端；Canvas 只在状态变化后重绘。
- 复杂指令拆解：支持“画一个太阳，下面有两座山，山前面有一棵树”和“画一个红色圆再画一个蓝色矩形”。
- 云端能力与成本控制：可选 OpenAI 兼容兜底，低置信度才触发；返回命令经过白名单校验；提供 `llmdemo=1` 本地模拟链路用于无密钥演示。
- 评审可复现性：右侧“运行评审演示”可一键覆盖复合场景、文字、背景、澄清追问、序号选择、云端兜底模拟、撤销重做和导出链路；运行看板实时展示对象数、历史步数、解析来源和最近动作；AI 兜底面板会明确展示当前 LLM 模式。
- 工程可靠性：75 个自动化测试覆盖命令解析、状态引擎、渲染器、LLM 兜底、OpenAI resolver、demo 回放、澄清追问、连续聆听和评审脚本数据。

## PR 交付规范

后续真实改动建议全部从分支发起 PR，并使用仓库内的 `.github/pull_request_template.md`。每个 PR 只做一件事，例如：

| PR | 范围 | 必填测试 |
| --- | --- | --- |
| 提交材料补强 | README、提交说明、设计文档、LICENSE、PR 模板 | `npm test` |
| 演示与部署修复 | GitHub Pages workflow、demo 回放入口 | `npm test`，在线地址 200 |
| 视频链接回填 | README 与提交平台链接 | 匿名窗口打开视频链接 |

每个 PR 描述至少包含：标题、功能、实现思路、测试结果。不要修改 commit 时间戳；把实际发生的补救工作拆成真实、可审查的提交即可。
